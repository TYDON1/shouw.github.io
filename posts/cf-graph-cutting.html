E. Graph Cutting 解题思路 ​

核心问题分析 ​

题意：给定一棵 nnn 个点的树。选三个互不相同的点 a<b<ca < b < ca<b<c，砍出包含这三个点的最小连通子图（也就是它们的斯坦纳树）。问有多少个三元组，使得砍出来的子图恰好有 ddd 个点。

多组数据，3≤d≤n≤20003 \le d \le n \le 20003≤d≤n≤2000，∑n≤2000\sum n \le 2000∑n≤2000，时限 222 秒。

n≤2000n \le 2000n≤2000 且 ∑n≤2000\sum n \le 2000∑n≤2000——这个范围几乎是在明说"O(n2)O(n^2)O(n2) 的树上背包"。

1. 三个点的斯坦纳树长什么样 ​

先想清楚要数的东西的形状。树上三个点 a,b,ca, b, ca,b,c 的最小连通子图，一定是一个 "Y" 字形：存在一个"中心"点 mmm，从 mmm 出发三条互不相交的路径分别通到 a,b,ca, b, ca,b,c。（如果某个点恰好在另外两个点的路径上，那么 YYY 退化成一条链，中心就是那个点本身，其中一条"路径"长度为 000。）

反过来看这个形状的关键特征：

这个子图的所有叶子，必须恰好是被选中的点。

因为如果有个叶子不是选中的点，把它删掉子图依然连通且依然包含 a,b,ca,b,ca,b,c，那它就不是"最小"的了。

所以问题变成：数有多少个连通子图，它恰好有 ddd 个点，且叶子恰好是 333 个（这 333 个叶子就唯一确定了三元组）。

2. 设计状态：把"叶子数"塞进 DP ​

以 111 为根做树形 DP。设

dp[u][i][k]=包含 u 的连通子图，大小为 i, 已经"钉住"了 k 个选中点，且是这些点与 u 的最小连通子图dp[u][i][k] = \text{包含 } u \text{ 的连通子图，大小为 } i,\ \text{已经"钉住"了 } k \text{ 个选中点，且是这些点与 } u \text{ 的最小连通子图} dp[u][i][k]=包含 u 的连通子图，大小为 i, 已经"钉住"了 k 个选中点，且是这些点与 u 的最小连通子图

kkk 只需要 1,2,31, 2, 31,2,3 三档。初值很自然：

cpp
sizes[u] = 1;
dp[u][1][1] = 1;   // u 自己就是一个选中点

现在合并一个儿子 vvv，有两种本质不同的方式。

3. 转移一：uuu 处发生分叉 ​

如果 uuu 已经积累了 y≥1y \ge 1y≥1 个选中点（来自之前的儿子或者 uuu 自己），现在再从 vvv 这边接上 x−y≥1x - y \ge 1x−y≥1 个，那就是在 uuu 处分叉：

cpp
for (int i = sizes[u]; i >= 1; i--) {
    for (int j = sizes[v]; j >= 1; j--) {
        for (int x = 2; x <= 3; x++) {
            for (int y = 1; y < x; y++) {
                dp[u][i + j][x] += dp[u][i][y] * dp[v][j][x - y];
            }
        }
    }
}

注意两边都要求至少有一个选中点（y≥1y \ge 1y≥1 且 x−y≥1x - y \ge 1x−y≥1）。这正是在保证"不能有白长的枝条"——每一个分叉出去的方向，末端都必须坐着一个选中点，否则这个子图就不是最小的了。

iii 和 jjj 都必须倒序枚举。因为我们在读 dp[u][i][⋅]dp[u][i][\cdot]dp[u][i][⋅] 的同时往 dp[u][i+j][⋅]dp[u][i+j][\cdot]dp[u][i+j][⋅] 里写，而 i+j>ii + j > ii+j>i，倒序保证了被写入的位置在这一轮里已经"读过"了，不会把新算出来的东西再当成旧状态用一次（经典的 01 背包倒序）。

4. 转移二：uuu 只是一根"传递棒" ​

另一种情况：uuu 自己不是选中点，也没有别的分支，整个结构只是从 vvv 的子树里长上来，顺路把 uuu 串上：

cpp
for (int j = 1; j <= sizes[v]; j++) {
    for (int k = 1; k <= 2; k++) {
        dp[u][j + 1][k] += dp[v][j][k];
    }
}

这里有个非常要命的细节：kkk 只循环到 222，绝对不能让 k=3k = 3k=3 往上传。

想想为什么。如果 vvv 的子树里已经凑齐了三个选中点，那它们的最小连通子图完全落在 vvv 的子树内，压根不包含 uuu。硬把 uuu 加上去，得到的子图就不是最小的了——那是在数一个不存在的方案。这一行 k <= 2 就是整道题的正确性命门。

5. 统计答案：每个三元组恰好在一个点被数到 ​

最后：

cpp
int ans = 0;
for (int i = 1; i <= n; i++) ans += dp[i][d][3];

为什么直接对所有点求和不会重复？考虑某个三元组的斯坦纳树 SSS，令 rrr 是 SSS 中深度最小（最靠近根）的那个点。

  • 对于 SSS 里除 rrr 以外的点，k=3k=3k=3 的状态永远凑不齐：要在某点凑齐 333，必须在那里做转移一的分叉，而 SSS 中只有 rrr 是"三个方向的汇合处"（严格说是 SSS 在有根意义下唯一的顶点）；
  • 对于 rrr 严格上方的点 uuu：三个选中点全在 uuu 的同一个儿子子树里，没法拆成两个都含选中点的分支，所以转移一用不上；而转移二又被 k≤2k \le 2k≤2 挡住了。dp[u][⋅][3]=0dp[u][\cdot][3] = 0dp[u][⋅][3]=0。

所以每个三元组恰好在 u=ru = ru=r 处被数一次，求和不重不漏。

6. 一个反直觉的坑：这题必须把 #define int long long 关掉 ​

dp 是一个 (n+1)×(n+1)×4(n+1) \times (n+1) \times 4(n+1)×(n+1)×4 的三维数组。n=2000n = 2000n=2000 时有 2001×2001×4≈1.6×1072001 \times 2001 \times 4 \approx 1.6 \times 10^72001×2001×4≈1.6×107 个格子。

  • 用 323232 位 int：646464 MB 数据；
  • 用 646464 位 long long：128128128 MB 数据。

内存限制只有 256256256 MB，后者加上容器开销必炸。所以这道题的模板宏里，#define int long long 必须注释掉。

那会不会溢出？答案上界是 (20003)≈1.33×109\binom{2000}{3} \approx 1.33\times10^9(32000​)≈1.33×109，而 int 的上界是 2.147×1092.147\times10^92.147×109——刚好塞得下，而且中间状态数的是"子结构方案数"，同样被这个上界卡住。惊险过关。

另外强烈建议把最内层写成 array<int, 4> 而不是 vector<int>(4)：后者会产生 4×1064\times10^64×106 次独立堆分配，光是 vector 头部和分配器元数据就能把内存拉到 225225225 MB 的悬崖边上（我第一发交上去实测就是这个数）。换成 array 之后内存直接砍掉一大半。

7. 复杂度 ​

树上背包的经典结论：形如 for i in [1, sizes[u]] for j in [1, sizes[v]] 的合并，总代价是 O(n2)O(n^2)O(n2)（每一对点 (x,y)(x, y)(x,y) 只会在它们的 LCA 处被枚举到恰好一次）。状态里 (x,y)(x, y)(x,y) 的组合只有 333 种，是常数。所以

O(n2)O(n^2) O(n2)

∑n≤2000\sum n \le 2000∑n≤2000，4×1064\times10^64×106 级别的运算，跑了 484484484 ms，稳。

回头看这道 ∗2300*2300∗2300 的题，DP 的骨架是标准的树上背包，真正的思维含量集中在两个地方：一是把"最小连通子图"翻译成"所有叶子都是选中点"这个可以被 DP 直接刻画的条件；二是想明白 k=3k=3k=3 不能向上传递——这两件事都是"看懂了觉得理所当然，没看懂就完全写不出来"的类型。至于那个 long long 的内存坑，则是纯粹的工程经验了。

CPP 代码实现 ​

cpp
// E. Graph Cutting

#include <bits/stdc++.h>
#define lg(x) (63 - __builtin_clzll(x))
#define all(x) (x).begin(), (x).end()
#define low_bit(x) ((x) & (-x))
#define pb push_back
#define db long double
// #define int long long   <- 这题内存卡得死，必须关掉
#define sz(x) (int)x.size()
#define endl "\n"

using namespace std;

void solve() {

    int n, d;
    cin >> n >> d;
    vector<vector<int>> g(n + 1);
    vector<int> sizes(n + 1);
    // dp[u][i][k]: 含 u、大小为 i、钉住 k 个选中点的最小连通子图方案数
    vector<vector<array<int, 4>>> dp(n + 1, vector<array<int, 4>>(n + 1, {0, 0, 0, 0}));

    for (int i = 1; i < n; i++) {
        int u, v;
        cin >> u >> v;
        g[u].pb(v);
        g[v].pb(u);
    }

    auto dfs = [&](auto& self, int u, int fa) -> void {

        sizes[u] = 1;
        dp[u][1][1] = 1;

        for (auto v : g[u]) {
            if (v == fa) continue;
            self(self, v, u);

            // 转移一：在 u 处分叉，两边都必须含选中点
            for (int i = sizes[u]; i >= 1; i--) {
                for (int j = sizes[v]; j >= 1; j--) {
                    for (int x = 2; x <= 3; x++) {
                        for (int y = 1; y < x; y++) {
                            dp[u][i + j][x] += dp[u][i][y] * dp[v][j][x - y];
                        }
                    }
                }
            }

            // 转移二：u 只是把 v 的结构往上串，k = 3 绝对不能传上来
            for (int j = 1; j <= sizes[v]; j++) {
                for (int k = 1; k <= 2; k++) {
                    dp[u][j + 1][k] += dp[v][j][k];
                }
            }

            sizes[u] += sizes[v];
        }
    };

    dfs(dfs, 1, 0);

    int ans = 0;
    for (int i = 1; i <= n; i++) ans += dp[i][d][3];
    cout << ans << endl;

}

signed main() {

    ios_base::sync_with_stdio(false);
    cin.tie(nullptr);

    int t = 1;
    cin >> t;

    while (t--) {
        solve();
    }

}
