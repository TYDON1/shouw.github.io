D. Fibonacci Paths 详细解题思路 ​

核心问题与数学性质 ​

本题要求找出有向图中所有长度 k≥2k \ge 2k≥2 的简单路径 v0→v1→⋯→vkv_0 \to v_1 \to \dots \to v_kv0​→v1​→⋯→vk​，使得路径上的顶点值序列 x0,x1,…,xkx_0, x_1, \dots, x_kx0​,x1​,…,xk​ 构成广义斐波那契数列。

广义斐波那契定义 ​

xi=xi−2+xi−1for i≥2x_i = x_{i-2} + x_{i-1} \quad \text{for } i \ge 2 xi​=xi−2​+xi−1​for i≥2

关键性质：隐式拓扑序 ​

由于题目保证所有顶点值 av≥1a_v \ge 1av​≥1，对于任何长度 ≥3\ge 3≥3 的合法路径，必然满足：

avi=avi−1+avi−2>avi−1a_{v_i} = a_{v_{i-1}} + a_{v_{i-2}} > a_{v_{i-1}} avi​​=avi−1​​+avi−2​​>avi−1​​

这意味着路径上的点权值是严格递增的（除了前两个点可能大小任意）。

  • 这一性质保证了我们不需要担心“环”的问题（除了长度为 2 的路径）。
  • 这也提示我们可以按照点权值 ava_vav​ 从小到大的顺序来处理边，这相当于在一个隐式的 DAG（有向无环图）上进行动态规划。

1. 动态规划状态定义 ​

我们需要知道路径的“末端”和“倒数第二个值”才能确定下一个值需要是多少。

  • 状态定义 DP[v][pre]DP[v][\text{pre}]DP[v][pre]： 表示以顶点 vvv 为终点**，且路径上倒数第二个顶点的值为 prev_val\text{prev\_val}prev_val 的合法斐波那契路径的总数。
  • 数据结构： 由于 ava_vav​ 范围可达 101810^{18}1018，且对于每个点 vvv，有效的入边数量有限，我们使用 std::map<long long, long long> 来存储每个点的 DP 状态，避免空间爆炸。

2. DP 转移与核心逻辑 ​

我们按照边的终点权值 ava_vav​ 对所有边进行排序。排序是为了保证当我们处理到点 vvv 时，所有可能作为 vvv 前驱的路径（权值更小的点）都已经计算完毕。

转移步骤（处理边 u→vu \to vu→v） ​

假设当前处理的边是 u→vu \to vu→v，当前路径的最后两项确定为 […,au,av][\dots, a_u, a_v][…,au​,av​]。

  1. 基础贡献（长度 k=2k=2k=2）： 边 (u,v)(u, v)(u,v) 本身构成一条合法路径 [au,av][a_u, a_v][au​,av​]（题目允许前两项任意）。

    count=1\text{count} = 1 count=1

  2. 路径扩展（长度 k≥3k \ge 3k≥3）： 我们需要寻找一个前驱点 prevprevprev，使得路径 prev→u→vprev \to u \to vprev→u→v 满足斐波那契性质。

    • 条件：av=aprev+aua_v = a_{prev} + a_uav​=aprev​+au​
    • 所需前驱值：needed=av−au\text{needed} = a_v - a_uneeded=av​−au​

    如果 needed>0\text{needed} > 0needed>0，我们查询 uuu 的 DP 表，看有多少条以 uuu 结尾且倒数第二个值为 needed\text{needed}needed 的路径。

    count=(1+DP[u][needed])(modMOD)\text{count} = (1 + DP[u][\text{needed}]) \pmod{MOD} count=(1+DP[u][needed])(modMOD)

  3. 状态更新：

    • 更新总答案：TotalAns=(TotalAns+count)(modMOD)\text{TotalAns} = (\text{TotalAns} + \text{count}) \pmod{MOD}TotalAns=(TotalAns+count)(modMOD)
    • 更新 DP 表：这条新路径现在以 vvv 结尾，倒数第二个值是 aua_uau​。

      DP[v][au]=(DP[v][au]+count)(modMOD)DP[v][a_u] = (DP[v][a_u] + \text{count}) \pmod{MOD} DP[v][au​]=(DP[v][au​]+count)(modMOD)

复杂度分析 ​

  • 排序：O(Mlog⁡M)O(M \log M)O(MlogM)
  • DP 转移：遍历 MMM 条边，每次在 Map 中查询和插入，耗时 O(log⁡(degree))O(\log (\text{degree}))O(log(degree)) 或 O(log⁡M)O(\log M)O(logM)。
  • 总复杂度：O(Mlog⁡M)O(M \log M)O(MlogM)，在 M=2⋅105M=2 \cdot 10^5M=2⋅105 下完全可接受。

3. C++ 代码实现 ​

cpp
#include <bits/stdc++.h>

using namespace std;

const long long MOD = 998244353;

struct Edge {
    int u, v;
};

void solve() {
    int n, m;
    cin >> n >> m;

    // a[i] 存储顶点 i 的值 (1-indexed)
    vector<long long> a(n + 1);
    for (int i = 1; i <= n; ++i) {
        cin >> a[i];
    }

    vector<Edge> edges(m);
    for (int i = 0; i < m; ++i) {
        cin >> edges[i].u >> edges[i].v;
    }

    // 关键步骤：按照终点值 a[v] 排序
    // 这保证了类似拓扑序的处理顺序：值小的点先处理，
    // 从而保证处理 u->v 时，以 u 结尾且值更小的路径已经计算完成。
    sort(edges.begin(), edges.end(), [&](const Edge& x, const Edge& y) {
        return a[x.v] < a[y.v];
    });

    // DP 状态: dp_sum[v] 是一个 map
    // Key: 倒数第二个值 (prev_val)
    // Value: 路径数量
    vector<map<long long, long long>> dp_sum(n + 1);

    long long total_ans = 0;

    for (const auto& e : edges) {
        int u = e.u;
        int v = e.v;

        // 1. 基础路径：仅包含边 (u, v) 的路径，长度为 2，总是合法的
        long long current_paths = 1; 

        // 2. 尝试扩展：寻找形如 ... -> prev -> u -> v 的路径
        // 根据斐波那契定义: a[v] = a[u] + a[prev]
        // 所以我们需要的前驱值是:
        long long needed = a[v] - a[u];

        if (needed > 0) {
            // 在 u 的状态中查找倒数第二个值为 needed 的路径数量
            auto it = dp_sum[u].find(needed);
            if (it != dp_sum[u].end()) {
                current_paths = (current_paths + it->second) % MOD;
            }
        }

        // 累计答案
        total_ans = (total_ans + current_paths) % MOD;

        // 更新 v 的状态：
        // 新生成的路径以 v 结尾，倒数第二个值显然是 a[u]
        long long& entry = dp_sum[v][a[u]];
        entry = (entry + current_paths) % MOD;
    }

    cout << total_ans << "\n";
}

int main() {
    ios_base::sync_with_stdio(false);
    cin.tie(nullptr);

    int t;
    cin >> t;
    while (t--) {
        solve();
    }
    return 0;
}
